# UI preview

Generated by running the real handlers against a fake Telegram client and
the real chat store, then stripping the HTML the client would send. The
data is example data, the layout is exactly what the bot produces.

In Telegram a panel arrives as a **rich message**: a real `<h2>` over a
real `<table>` (Bot API 10.3). A preview cannot send one, so each screen
is shown in its classic form — the same tables drawn in `<pre>`, which
is exactly what the bot falls back to if Telegram ever refuses a rich
message. Button presses edit the rich message in place
(`edit_message_text(rich_text=...)`), so navigating keeps the native
table instead of dropping to the grid.
